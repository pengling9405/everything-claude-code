# /learn - 提取可复用模式

分析当前会话，提取值得保存为 skill 的模式。

## 触发时机

当你在一次会话中解决了一个非平凡问题时，都可以运行 `/learn`。

## 要提取什么

重点寻找：

1. **错误修复模式**
   - 出现了什么错误？
   - 根因是什么？
   - 最终是如何修好的？
   - 这种方法能否复用于类似错误？

2. **调试技巧**
   - 不显而易见的调试步骤
   - 有效的工具组合
   - 诊断模式

3. **Workaround**
   - 库的特殊行为
   - API 限制
   - 特定版本修复方式

4. **项目特定模式**
   - 新发现的代码库约定
   - 做出的架构决策
   - 集成方式

## 输出格式

在 `~/.claude/skills/learned/[pattern-name].md` 下创建一个 skill 文件：

```markdown
# [描述性模式名称]

**Extracted:** [日期]
**Context:** [适用场景的简要描述]

## Problem
[这个模式解决的具体问题]

## Solution
[模式 / 技术 / workaround]

## 示例
[如果适用，提供代码示例]

## When to Use
[什么触发条件下应激活该 skill]
```

## 流程

1. 回顾当前会话中可提取的模式
2. 找出最有价值、最可复用的洞察
3. 起草 skill 文件
4. 保存前先征求用户确认
5. 保存到 `~/.claude/skills/learned/`

## 注意事项

- 不要提取太琐碎的修复（如拼写错误、简单语法错误）
- 不要提取一次性问题（例如某次外部 API 故障）
- 优先提取未来能节省时间的模式
- 每个 skill 只聚焦一个模式
